# QA — frontend и регресс CorpLunch

## Область проверки

Владелец frontend/QA: Шишков. Контракты: [api.md](api.md), [roles.md](roles.md), [ui.md](ui.md). Демо не доказывает корректность серверного cutoff, JWT, SQL или реального MealtyProvider. Серверные проверки выполняются после реализации соответствующих модулей Бондарём/Пягаем.

При каждом прогоне записывать дату, версию/коммит, браузер, размер viewport, режим (demo/live), результат и ссылку на баг. Дефекты оформлять по шаблону `.github/ISSUE_TEMPLATE/bug_report.md`. Критические блокеры: потеря плана, редактирование после cutoff, неверная сумма, доступ к чужим данным, попадание unavailable в закупку.

## Минимальный регресс перед сдачей

1. Выполнить команды проверок из [frontend.md](frontend.md).
2. Пройти сценарий двух сотрудников → закрытие дня → экспорт → placed → статистика на desktop и телефоне.
3. Пройти админку: создать отдел и сотрудника, изменить статус, сохранить настройки.
4. Пройти ручные live-проверки ниже после готовности backend; отдельно проверить Compose с чистой БД.
5. Открыть CSV/XLSX в Excel или LibreOffice; убедиться, что кириллица и лист «По сотрудникам» читаются.

## Чек-лист входа и ролей

- [ ] Пустая/невалидная почта и пустой пароль не отправляют форму.
- [ ] Неверные данные → понятная ошибка, повторная попытка доступна.
- [ ] Сотрудник, второй сотрудник, закупки, админ попадают на свой экран.
- [ ] Прямой переход сотрудника на `/admin`, `/orders`, `/stats` возвращает в каталог.
- [ ] Закупки не видят управление; прямой переход `/admin` недоступен.
- [ ] Реальный вход отправляет Bearer без cookies; пароль не попадает в localStorage.
- [ ] Перезагрузка восстанавливает сессию; выход очищает токен и данные предыдущего пользователя из кэша.
- [ ] Истёкший JWT / отключённый пользователь → 401 и повторный вход (live).
- [ ] Поздний 401 запроса предыдущей сессии не сбрасывает новый вход.
- [ ] Подмена роли в браузере не даёт прав на сервере (live).
- [ ] Демо включается только явным выбором; API-ошибка не превращается в успех демо.

## Чек-лист сотрудника

- [ ] Есть состояния загрузки, ошибки, пустого каталога и пустого результата поиска.
- [ ] Поиск без учёта регистра, фильтры категорий и их сочетание работают.
- [ ] Цена отображается в ₽; 41005 коп. → 410,05 ₽.
- [ ] Карточка показывает название, уточнение, вес, калории, КБЖУ/описание; nullable-поля не дают `null` в тексте.
- [ ] Добавление, увеличение, уменьшение и удаление последней единицы меняют сумму.
- [ ] Несохранённый план заметен; смена даты требует подтверждения; обновление страницы предупреждает.
- [ ] Сохранение отправляет полный состав только с `dish_id`/`qty`; после повторного входа план восстановлен.
- [ ] Во время сохранения дата не переключается; после завершения переключатель снова доступен.
- [ ] После 403 и закрытия дня показывается сохранённый сервером состав, а не несохранённые изменения. После 422 открытый черновик остаётся доступен для исправления.
- [ ] У двух сотрудников независимые планы на одну дату.
- [ ] Персональный лимит блокирует сохранение; системный лимит проверяется сервером, 422 показан без потери черновика.
- [ ] Дата на границе месяца/года выбирается корректно.
- [ ] При server `editable=false` нельзя добавлять/менять состав.
- [ ] Live: 15:59:59 накануне — сохранение разрешено; ровно 16:00 — 403, включая уже открытую страницу.
- [ ] Изменившаяся фактическая цена видна рядом с плановой; unavailable помечен «Нет в меню Mealty».
- [ ] На телефоне доступны каталог и план; после перехода между вкладками состав сохранён в черновике.

## Чек-лист закупок

- [ ] Сводка меняется при выборе даты; пустой день объяснён.
- [ ] До закрытия суммы обозначены предварительными; экспорт и placed недоступны.
- [ ] Обновление каталога: успех / 429 / 502; при сетевой ошибке последнее меню не исчезает (live).
- [ ] Закрытие требует подтверждения; во время запроса повторное действие заблокировано.
- [ ] После закрытия агрегируются количества двух сотрудников, используются фактические цены.
- [ ] Недоступные блюда исключены из таблицы и суммы закупки, но остаются в персональном составе с предупреждением.
- [ ] Повторный cutoff и place не меняют суммы и не создают дубликаты (live; демомодель покрыта unit-тестом).
- [ ] Раскрываются составы сотрудников; редактирование чужого плана отсутствует.
- [ ] CSV имеет `external_id,name,qty,unit_price_kopecks,line_total_kopecks`, суммы целочисленные.
- [ ] XLSX открывается как настоящий Excel-файл; есть лист «По сотрудникам».
- [ ] Успешный экспорт меняет статус; ошибка скачивания не показывает успешную выгрузку.
- [ ] «Заказ размещён» требует подтверждения ручного размещения; повторное нажатие отключено.

## Чек-лист статистики

- [ ] Даты и отдел фильтруют отчёт; начало позже конца показывает ошибку без запроса.
- [ ] Пустой период объяснён, не показан выдуманный график.
- [ ] Итог и дельта соответствуют закрытым заказам выбранного периода.
- [ ] Отделы, сотрудники, топ блюд и изменения цен соответствуют ответу API.
- [ ] Закупки не обращаются к admin-only API для получения фильтра отделов.

## Чек-лист администратора

- [ ] Можно создать и переименовать отдел, пустое название не принимается.
- [ ] Создание сотрудника: почта, имя, пароль, роль, отдел, лимит, активность.
- [ ] Изменение сотрудника сохраняет роль/отдел/лимит/активность; PATCH не посылает email.
- [ ] Пустой новый пароль не сбрасывает существующий; своё поле пароля в этом списке не показывается.
- [ ] Дублирующаяся почта и серверная валидация дают понятную ошибку.
- [ ] Общий лимит: пусто → null, 0 → 0, 700,50 → 70050; отрицательные суммы и >2 знаков после запятой отвергаются.
- [ ] Настройки cutoff/города/квоты/лимита сохраняются полным PUT; часовой пояс сохраняется.
- [ ] Пока сохраняется пользователь/отдел/настройки, нельзя изменить отправляемую форму или переключить её на другой объект; после ответа блокировка снимается.
- [ ] Администратор не может редактировать чужие планы.

## Вёрстка и доступность

- [ ] 1440, 1280, 768, 390 и 320 px: нет горизонтального скролла страницы; широкие таблицы прокручиваются внутри панели.
- [ ] Все поля подписаны, кнопки количества имеют имя блюда в accessible name.
- [ ] Tab/Shift+Tab/Enter работают; фокус виден; ошибки объявляются через `role=alert`.
- [ ] Масштаб 200%, длинные имена и названия, отсутствие фото не перекрывают действия.
- [ ] Цвет не единственный индикатор ошибки/статуса; анимация отключена при reduced motion.

## HTML-фикстура

Файлы и происхождение описаны в [fixtures/README.md](../backend/tests/fixtures/README.md). Frontend-тест проверяет только сохранность HTML и ожидаемых полей. Существующий `backend/tests/test_mealty_parser.py` проверяет парсер на исходной `mealty_catalog.html`; frontend QA использует отдельную `mealty_catalog_qa.html`. Интеграционные проверки исчезновения блюда и пустого ответа → 502 без массового unavailable остаются отдельным шагом приёмки sync. CI не обращается к Mealty.

## Блокеры интеграционной приёмки

- В backend уже есть login/me, управление пользователями и отделами, парсер Mealty. Каталог, планы, заказы, статистика и настройки ещё требуют реализации HTTP API и интеграционной проверки. Live end-to-end пока нельзя считать пройденным.
- Генерация API-клиента ожидает полной стабильной OpenAPI-схемы; сейчас DTO и пути соответствуют `docs/api.md`.
- В контракте нет статистики по дням и отдельного cutoff-времени для сотрудника. UI использует server `editable`, не выдумывает точное время закрытия конкретного плана.
- Открытие экспортов в настоящем Excel/LibreOffice и Safari/Firefox остаётся ручной приёмкой.

Результаты текущего прогона: [qa-results.md](qa-results.md). Незаполненные пункты выше — повторяемый шаблон, а не заявление, что они уже прошли.
