# Повторная проверка — 21.09.2026

Проверены исходники frontend, обработка асинхронных запросов, прежний регресс и новые сценарии ошибок. Исходный набор из 14 тестов проходил, но не проверял обнаруженные ниже случаи. Новые тесты сначала воспроизвели ошибки, затем прошли после исправлений.

| Проверка | Результат повторного прогона |
|---|---|
| ESLint | PASS, без предупреждений |
| Prettier check | PASS |
| Vitest | PASS, 22 теста / 7 файлов |
| Strict TypeScript + Vite build | PASS |
| Playwright / Edge | PASS, 6 сценариев на desktop и мобильном viewport |

Исправлено:

1. **Несохранённый состав после cutoff.** После ответа 403 и обновления закрытого плана локальный черновик оставался рядом с серверным итогом. Теперь при `editable=false` отображается только серверный состав и снимается отметка несохранённых изменений. Ошибка 422 при открытом дне, напротив, сохраняет черновик для исправления.
2. **Смена даты во время сохранения плана.** Завершение старого запроса могло сбросить признак изменений уже другой даты. Календарь и стрелки блокируются до окончания сохранения. Повторный выбор той же даты ничего не сбрасывает.
3. **Несогласованные цены черновика.** У `draft` с уже закрытым редактированием строка использовала текущую цену каталога, а итог — старую. Теперь обе суммы используют одну текущую цену до перехода в зафиксированный статус.
4. **Поздний 401 предыдущей сессии.** Ответ от старого запроса мог удалить токен нового входа. Очистка сессии выполняется только если её токен по-прежнему совпадает с токеном запроса.
5. **Параллельное редактирование в админке.** Во время сохранения можно было начать другую форму пользователя/отдела или изменить ещё не отправленные настройки, после чего завершение запроса закрывало новую форму либо показывало неверное сообщение о сохранении. На время запроса блокируются соответствующие поля и переключение редактируемого объекта.

Добавлены компонентные регрессии в `frontend/src/pages/Catalog.test.tsx` и `Admin.test.tsx`, а также тест запоздалого 401 в `api.test.ts`. Полный browser-регресс повторён после изменений форм. Ограничения интеграционной приёмки ниже остаются в силе: эти frontend-тесты не подтверждают работу реального backend API, серверного парсера или живого Mealty.

## Найдено и исправлено в этом прогоне

- На мобильном экране admin grid растягивался по ширине таблицы, кнопка создания оказывалась недоступной: добавлен `min-width: 0` дочерним grid-блокам.
- На 320 px скрытая подпись заголовка таблицы создавала переполнение страницы: контейнер таблицы стал позиционированным.
- Ошибка HTTP долго скрывалась за повторными запросами: один повтор с задержкой 500 мс, затем видимая ошибка.
- Выход мог потерять несохранённый план: добавлено подтверждение выхода.
- Для зафиксированного плана без фактической цены UI мог показывать новую цену каталога: теперь используется сохранённая плановая цена.
- Во время cutoff/export/place можно было переключить дату и получить неоднозначный результат: переключатель заблокирован на время операции.
- Уточнены неоднозначные селекторы в e2e админки; исходная попытка использовать отсутствующий Chrome заменена параметром браузерного канала.
