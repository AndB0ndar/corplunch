# Работа команды

Проект **CorpLunch**. Трое человек. Классические роли совмещаются с разработкой: каждый пишет код, но сложность разная. Один профессиональный программист — **Бондарь А.Р.**; остальные двое умеют программировать слабее и идут по шаблонам и ревью тимлида.

Роли **в продукте** (`employee` / `procurement` / `admin`) — это пользователи системы, не команда. См. [roles.md](roles.md).

## Состав

| Человек | ФИО | Классические роли | Как разработчик |
|---------|-----|-------------------|-----------------|
| **1** | Бондарь А.Р. | тимлид, архитектор, DevOps | ведущий backend: парсер, cutoff, цены, сводка, stats, ревью |
| **2** | Пягай | технический писатель | простой backend по шаблону: auth/users/settings, seed, CLI фикстуры, хелперы лимита/429, pytest по контракту, CSV |
| **3** | Шишков | QA | frontend: все экраны [ui.md](ui.md), включая админку, по OpenAPI |

Почему так:

- DevOps на маленьком монолите — Compose и `.env`, это быстрее сделать ведущему, чем учить второго с нуля.
- Второй не проектирует домен, но закрывает понятный CRUD и **документацию**, без которой команда и защита разъезжаются.
- Третий держит UI и качество: чек-листы, регресс, фикстура HTML для парсера.

## Бондарь А.Р. — тимлид, ведущий разработчик, DevOps

**Тимлид:** этапы, приоритет, контракт OpenAPI, review всех PR, спорные места (cutoff, правило цены), защита.

**DevOps (проект небольшой):** `docker-compose`, `.env.example`, чтобы `up --build` работал с нуля; простой CI (`pytest` без сети). Не Kubernetes, не отдельный кластер.

**Ведущий разработчик:** ядро — `providers`, `catalog`, `planning`, `orders` (агрегат, cutoff, `place`), `stats`, jobs sync/cutoff. Образец для Пягая — вертикальный срез отделов: `GET`/`POST /api/admin/departments` (модель, миграция, schema, router, pytest) плюс `GET /api/health`. Login, таблицу `users` и `PATCH` отделов не пишет. Скелет React (Vite, роутер, тонкий клиент API, без генерации из OpenAPI) — без экранов. Простой CI (`pytest` без сети) — в том же каркасе этапа 0.

Не рисует экраны и не пишет пользовательские чек-листы — это Шишков. Не ведёт README в одиночку и не закрывает admin CRUD целиком — это Пягай (дописывает пакет отделов и остальной admin/auth).

## Пягай — простой backend и технический писатель

**Технический писатель:** актуальность [README](../README.md) и `docs/` под код; формулировки API вместе с тимлидом; как запустить, демо-текст, подписи в UI совместно с фронтом. Документ врёт — это баг его зоны.

**Разработчик:** модули по **готовому шаблону** Бондаря, без проектирования ядра:

- `auth/` и admin API по образцу отделов Бондаря: логин, bcrypt, `GET /api/me`, `PATCH` отделов, CRUD пользователей, `GET/PUT /api/admin/settings` (cutoff/город/лимит/квота sync — **хранение**, не формула дня). `GET`/`POST` отделов уже лежат в каркасе — не переписывать с нуля.
- CLI: `seed-users` (отделы и демо-учётки, **два сотрудника** для сценария сводки), `sync-from-fixture` — вызывает парсер Бондаря на HTML-фикстуре, селекторы не трогает.
- Хелперы, которые ядро только вызывает: дневной лимит → 422; счётчик sync за сутки → 429.
- Pytest по [api.md](api.md) / [roles.md](roles.md): 401/403, неактивный пользователь, cutoff → 403, идемпотентность `place`/`cutoff`, `conftest` с тремя ролями.
- Рендер CSV/XLSX из готового DTO сводки (колонки из [api.md](api.md)); статус `locked → exported` остаётся в роутере заказов.

Не проектирует парсер Mealty, не меняет селекторы, не пишет алгоритм cutoff, `actual_price_kopecks`, агрегат сводки и `GET /stats/summary`.

Ревью кода — у Бондаря. Стиль docs — у Пягая, факты домена сверяет с тимлидом.

## Шишков — frontend и QA

**QA:** чек-листы сотрудника / закупок / админа; регресс к демо; HTML-фикстура Mealty для тестов парсера; баги в issue, не «тихо на своей машине». Сценарий [demo.md](demo.md) гоняет перед защитой.

**Разработчик:** все экраны MVP — вход, каталог+план, сводка, статистика, **админ (люди, отделы, settings)**. Админ-экран начинается, как только живы `users`/`settings` (конец этапа 0 / этап 1), не откладывается к защите. Сначала мок по [api.md](api.md), потом живой API. Не пишет SQL и не парсит HTML в браузере.

Сложный стейт и кривой контракт — эскалация к тимлиду, не «угадать в UI».

## Параллельность

| Пока Бондарь … | Пягай | Шишков |
|----------------|------------|------------|
| Compose + образец отделов + скелет API, затем парсер | README, auth, дописать admin по образцу, seed двух сотрудников | макет входа, чек-лист логина |
| sync каталога, цены | `sync-from-fixture`, хелперы лимита и 429, docs каталога | сетка каталога; **админ-экран**, как только живы users/settings |
| планы, cutoff | docs cutoff + pytest 403/ролей/идемпотентности; CSV на фикстуре DTO | календарь плана, кейсы «после 16:00» |
| сводка, stats API | экспорт под живой агрегат, текст демо | сводка и графики, регресс |

Правило: не ждать конца этапа. Ждём тонкий JSON-контракт, не всю бизнес-логику.

## Git и контракт

Поставка кода — GitHub Flow, метод команды — облегчённый Scrum, см. [process.md](process.md).

- Ветки: `feature/catalog-parser`, `feature/users-seed`, `feature/catalog-page`, …
- PR с «зачем»; фронт — скрин, backend — pytest, docs — что изменилось в оглавлении.
- Секреты не коммитить.
- Ломающий OpenAPI — только с согласия тимлида; фронт чинится в том же PR или сразу следом.
- Шишков не пишет SQL. Пягай не меняет селекторы Mealty. Админ-экран — Шишков, admin API — Пягай. Бондарь не мержит в `main` без зелёного локального запуска.

## Локальная разработка

1. `.env.example` (зона DevOps / Бондарь).
2. `docker compose up --build`.
3. Frontend: прокси `/api` → `:8000`.
4. Тесты backend: `pytest`, без живого mealty.ru.

## Definition of Done

- Миграция, если менялась схема.
- Тест, чек-лист QA или явный ручной шаг в PR.
- OpenAPI и `docs/` не расходятся с кодом (писатель).
- `docker compose up` с нуля работает (DevOps / Бондарь).
