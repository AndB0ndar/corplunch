# Работа команды

Проект **CorpLunch**. Трое человек. Классические роли совмещаются с разработкой: каждый пишет код, но сложность разная. Один профессиональный программист — **Бондарь А.Р.**; остальные двое умеют программировать слабее и идут по шаблонам и ревью тимлида.

Роли **в продукте** (`employee` / `procurement` / `admin`) — это пользователи системы, не команда. См. [roles.md](roles.md).

## Состав

| Человек | ФИО | Классические роли | Как разработчик |
|---------|-----|-------------------|-----------------|
| **1** | Бондарь А.Р. | тимлид, архитектор, DevOps | ведущий backend: парсер, cutoff, цены, сводка, stats, ревью |
| **2** | Пягай | технический писатель | простой backend по шаблону: users/settings, seed, CSV |
| **3** | Шишков | QA | frontend: экраны по [ui.md](ui.md) и OpenAPI |

Почему так:

- DevOps на маленьком монолите — Compose и `.env`, это быстрее сделать ведущему, чем учить второго с нуля.
- Второй не проектирует домен, но закрывает понятный CRUD и **документацию**, без которой команда и защита разъезжаются.
- Третий держит UI и качество: чек-листы, регресс, фикстура HTML для парсера.

## Бондарь А.Р. — тимлид, ведущий разработчик, DevOps

**Тимлид:** этапы, приоритет, контракт OpenAPI, review всех PR, спорные места (cutoff, правило цены), защита.

**DevOps (проект небольшой):** `docker-compose`, `.env.example`, чтобы `up --build` работал с нуля; простой CI (`pytest` без сети). Не Kubernetes, не отдельный кластер.

**Ведущий разработчик:** ядро — `providers`, `catalog`, `planning`, `orders`, `stats`, jobs sync/cutoff. Первый эндпоинт как образец для Пягая. Скелет React (Vite, роутер, клиент API), чтобы Шишков не проектировал архитектуру фронта.

Не рисует все экраны и не пишет пользовательские чек-листы — это Шишков. Не ведёт README в одиночку — это Пягай.

## Пягай — простой backend и технический писатель

**Технический писатель:** актуальность [README](../README.md) и `docs/` под код; формулировки API вместе с тимлидом; как запустить, демо-текст, подписи в UI совместно с фронтом. Документ врёт — это баг его зоны.

**Разработчик:** модули по **готовому шаблону** Бондаря: пользователи, отделы, settings (cutoff/город — хранение, не алгоритм фиксации дня), seed учёток, выгрузка CSV/XLSX. Не проектирует парсер Mealty, `actual_price_kopecks` и агрегацию сводки.

Ревью кода — у Бондаря. Стиль docs — у Пягая, факты домена сверяет с тимлидом.

## Шишков — frontend и QA

**QA:** чек-листы сотрудника / закупок / админа; регресс к демо; HTML-фикстура Mealty для тестов парсера; баги в issue, не «тихо на своей машине». Сценарий [demo.md](demo.md) гоняет перед защитой.

**Разработчик:** вход, каталог+план, сводка, статистика. Сначала мок по [api.md](api.md), потом живой API. Не пишет SQL и не парсит HTML в браузере.

Сложный стейт и кривой контракт — эскалация к тимлиду, не «угадать в UI».

## Параллельность

| Пока Бондарь … | Пягай | Шишков |
|----------------|------------|------------|
| Compose + скелет API, затем парсер | README/запуск, auth/users по шаблону | макет входа, чек-лист логина |
| sync каталога, цены | описание каталога в docs/api, seed блюд из фикстуры | сетка каталога на моке |
| планы, cutoff | раздел «как считается cutoff» в docs, settings | календарь плана, кейсы «после 16:00» |
| сводка, stats API | CSV-выгрузка по образцу, текст демо | сводка и графики, регресс |

Правило: не ждать конца этапа. Ждём тонкий JSON-контракт, не всю бизнес-логику.

## Git и контракт

Поставка кода — GitHub Flow, метод команды — облегчённый Scrum, см. [process.md](process.md).

- Ветки: `feature/catalog-parser`, `feature/users-seed`, `feature/catalog-page`, …
- PR с «зачем»; фронт — скрин, backend — pytest, docs — что изменилось в оглавлении.
- Секреты не коммитить.
- Ломающий OpenAPI — только с согласия тимлида; фронт чинится в том же PR или сразу следом.
- Шишков не пишет SQL. Пягай не меняет селекторы Mealty. Бондарь не мержит в `main` без зелёного локального запуска.

## Локальная разработка

1. `.env.example` (зона DevOps / Бондарь).
2. `docker compose up --build`.
3. Frontend: прокси `/api` → `:8000`.
4. Тесты backend: `pytest`, без живого mealty.ru.

## Definition of Done

- Миграция, если менялась схема.
- Тест, чек-лист QA или явный ручной шаг в PR.
- OpenAPI и `docs/` не расходятся с кодом (писатель).
- `docker compose up` с нуля работает (DevOps / Бондарь).
