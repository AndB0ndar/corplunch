# Цели и границы MVP

Продукт: **CorpLunch** (`corplunch`) — система заказа еды в офис.

## Проблема

Сотрудники офиса хотят заказывать готовую еду с корпоративного сайта (пока только Mealty). Если каждый заказывает сам — закупки не видят объём, цены «плывут», а к дате доставки блюдо может уже стоить иначе или исчезнуть из меню.

## Решение

Внутренняя система:

1. Периодически снимает каталог Mealty (название, цена, категория, КБЖУ, наличие).
2. Даёт сотруднику календарный план на несколько дней вперёд.
3. В момент cutoff фиксирует планы, обновляет цены и собирает сводный заказ офиса.
4. Отдаёт закупкам таблицу «блюдо × количество × сумма», персональную разбивку, экспорт и статистику.

Оплата и клик «оформить» на mealty.ru **не автоматизируются**. Закупки переносят сводку вручную.

## Критерии готовности MVP

- Сотрудник логинится и составляет план на дату.
- До cutoff план можно менять; после — нельзя.
- После cutoff у позиций есть `actual_price` либо флаг `unavailable`.
- Закупки открывают сводку дня, выгружают CSV/XLSX, отмечают заказ размещённым.
- Есть отчёт за период: сумма, топ блюд, расход по отделам, отклонение план/факт.
- Парсер Mealty покрыт тестом на сохранённом HTML (CI не ходит на сайт).
- Проект поднимается через Docker Compose, роли и демо-пользователи сидятся из seed.



## Вне MVP

- Автозаказ / корзина на mealty.ru.
- Оплата и биллинг сотрудников.
- Второй провайдер еды (закладываем только интерфейс `FoodProvider`).
- Мобильное приложение.
- SSO / Active Directory.
- Сложные согласования руководителя (достаточно ролей и лимита ₽/день, если включён).



## Нефункциональные требования

- Учебный проект на 3 человека, параллельные модули.
- Каталог не дёргаем чаще 1–2 раз в сутки + ручной refresh у закупок.
- Город по умолчанию — Москва (цены Mealty зависят от города).
- Русский язык интерфейса.
