## Найденный дефект реализованного API

### ADMIN-B01 — ответ API пользователей не содержит is_active

**Статус:** CLOSED, исправлено и проверено 30.09.2026. **Область:** backend, сериализация пользователей.

Шаги воспроизведения:

1. Войти администратором и открыть управление.
2. Создать сотрудника с выключенной активностью. Создание успешно, вход этого сотрудника возвращает 401.
3. Посмотреть ответ создания и таблицу после обновления списка.

**Ожидается:** [GET /api/admin/users](../../api.md) возвращает булево `is_active`; таблица показывает «Отключён» или «Активен» согласно серверным данным.

**До исправления:** поле отсутствовало. Это подтверждено ответом создания (`statusFieldReturned: false` в доказательствах от 29.09), загруженной таблицей и схемой `backend/app/users/schemas.py`: `UserOut` не объявлял `is_active`. Строгий браузерный тест 30.09 перед исправлением упал: ожидалось false, получено undefined.

**Исправление:** в `UserOut` добавлено обязательное булево поле `is_active`, читаемое из модели пользователя. Оно возвращается при создании, получении списка, изменении пользователя и в `/api/me`. Поле уже есть в БД, миграция не требуется. Пример `/api/me` в `docs/api.md` дополнен. Защитное поведение frontend для старого API сохранено.

**Проверка:** при создании отключённого сотрудника API возвращает false, таблица показывает «Отключён», вход даёт 401. Правка имени оставляет false и 401. Явное включение возвращает true, вход даёт 200, `/api/me` содержит true; после обновления страницы таблица показывает «Активен». Серверный регресс дополнительно проверяет активного пользователя и переход в отключённое состояние. Отсутствие поля теперь приводит к падению теста, а не только записывается как наблюдение.

## Повторение live-проверки

Использовать отдельную QA-базу. Из корня репозитория:

```powershell
docker compose --env-file tests/.env.test up -d --build db api
docker compose --env-file tests/.env.test exec api python -m app.cli seed-users
Set-Location frontend
$env:API_PROXY_TARGET='http://127.0.0.1:18000'
npm run dev -- --host 127.0.0.1 --port 5181 --strictPort
```

В другом терминале, в `frontend/`:

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:5181'
npx playwright test --config=playwright.admin-live.config.ts
```

Сценарий создаёт отдел и сотрудника с уникальным адресом в QA-базе. Сырой результат — `tests/results/admin-results.json`, снимок — `frontend/test-results/live-admin/`. После проверки остановить Vite и выполнить из корня `docker compose --env-file tests/.env.test stop`. Снимки и отчёт, добавленные в репозиторий, относятся только к указанному прогону.
