# Роли и сценарии

## Роли

| Роль | Экран | Права |
|------|--------|--------|
| **employee** | каталог + свой план | читать меню, редактировать свой draft до cutoff |
| **procurement** | сводка, статистика | sync каталога, ручной cutoff, экспорт, placed, чужие планы на чтение |
| **admin** | всё + настройки | пользователи, отделы, cutoff, город, лимиты; чужие планы — только чтение |

Учётка может быть сразу `admin` — это супермножество закупок, кроме правки чужих планов (`PUT /plans` только у employee).

## Сценарий сотрудника

1. Входит как `employee@kis.local`.
2. Выбирает дату доставки в календаре (сегодня править уже нельзя, если cutoff вчера прошёл).
3. Фильтрует каталог по категории / поиску.
4. Добавляет блюда в план. Видит ориентировочную сумму.
5. Если лимит задан — не может сохранить план выше лимита.
6. После cutoff открывает тот же день: позиции заблокированы, часть с новой ценой, часть с пометкой «нет в меню».

## Сценарий закупок

1. Входит как `procurement@kis.local`.
2. При необходимости жмёт «Обновить каталог».
3. Открывает дату поставки. До cutoff видит черновики (`collecting`); после — зафиксированную сводку.
4. Для демо (не ждать 16:00) жмёт «Закрыть приём заказов» → `POST /api/orders/{date}/cutoff`.
5. Смотрит агрегат по блюдам и кто что заказал.
6. Скачивает CSV/XLSX, переносит заказ на mealty.ru вручную.
7. Жмёт «Заказ размещён».
8. На экране статистики смотрит неделю/месяц: расход, отделы, топ блюд, дельту цен.

## Сценарий админа

1. Заводит отделы (`POST /api/admin/departments`) и сотрудников (`POST /api/admin/users`).
2. Задаёт cutoff (например 16:00) и город Москва в настройках.
3. По желанию включает дневной лимит (`daily_limit_kopecks`).
4. Чужие планы смотрит через сводку или `GET /api/plans/{date}?user_id=`, не редактирует.

## Cutoff — как считать

Для даты доставки `D` правки разрешены, пока `now < (D - 1 день) + cutoff_time` в `Europe/Moscow`.

Пример: cutoff 16:00, доставка в среду. Редактировать план среды можно до **вторника 16:00**. После этого job фиксирует среду.

## Уведомления в UI (без почты в MVP)

На карточке плана:

- цена выросла/упала относительно `planned_price_kopecks`;
- блюдо снято (`unavailable`) — предложить открыть каталог и заменить до cutoff; после cutoff только показать факт.
